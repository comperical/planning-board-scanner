- Add a `scan_log` table (plan_db.py) distinct from `analysis_log`.
  `analysis_log` records a manual pass over one already-downloaded document
  looking for projects; there's no equivalent record of when a town's
  website was last checked/re-scanned for new documents to download in the
  first place. Right now "least recently scanned" can only be estimated by
  proxy (working/<town>/ file mtimes, or the towninfo/*.md "Investigated:"
  date, which is really "last researched for site-access notes", not "last
  checked for new files"). Want one row per scan pass, keyed by town_id,
  with a timestamp (and maybe a note/counts of new files found) - lets the
  towns.wisp page's "Next Up" logic (and any future scan-scheduling) be
  driven by real data instead of file mtimes.
